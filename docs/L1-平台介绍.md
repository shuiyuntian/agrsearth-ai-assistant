# L1 平台介绍

## 1.1 定位：航遥业务中台

**航遥业务中台**是 AI 驱动的 GIS 数据展示与分析平台，组织关系如下：

```text
航遥业务中台（平台整体）
├── 18850 管理面 = 业务中台的后端管理入口（ruoyi-admin：资源/扩展/系统/监控管理）
└── 18880 GIS 球平台 = 业务中台中的一个应用，定名「航遥时空大数据平台」
    └── 插件体系（能力包）：二维分类 track（工具轨/系统轨）× tier（平台/业务）+ delivery（标配/选装）
```

- **中台**提供统一底座：SSO 统一身份、网关鉴权、资源中心（MinIO + resource-manager）、
  Nacos 配置、运维监控；**应用与插件**全部跑在底座之上，不各自重复造。
- **AI 集成**：MCP（Model Context Protocol）+ AI SDK，AI 助手（ai-assistant-mcp）是
  「系统轨也可以有球平台前端」的实证先例。

## 1.3 二维分类模型：track × tier（+ delivery）

> 契约本体见平台仓 `docs/插件开发指南/4-契约参考/PLUGIN_DEVELOPMENT.md` §2.2；本节为入门叙事，判轨/填字段以本体为准。

- **track（轨）= 复杂度/体量维**：`tool`（轻量：≤1 个自建后端、不引入复杂三方组件）/
  `system`（子系统：可含三方组件、多组件后端，**也可以有球端面板**——ai-assistant-mcp 先例）。
- **tier（归属）= 服务于谁**：`platform`（服务平台自身/治理机制，如 sso、help-center）/
  `business`（服务业务场景；basemap/measure 等全员标配能力仍属 business）。
- **delivery（交付）= 标配/选装**：仅 tool·business 象限用——`bundled`（随平台标配交付）/
  `optional`（按项目选装）；其余象限不填。
- manifest 的 `track`/`tier` **显式必填、零推断**（缺失/非法 publish 即拒）；仓内目录唯一规则
  `extensions/<track>/<tier>/<pkg>/`，publish 闸口机器校验「目录==分类」。
- 管理 UI 按轨独立菜单：**系统扩展 / 系统实例 / 工具扩展 / 工具实例**，页内按 tier 分组。

| | 工具轨（track: tool） | 系统轨（track: system） |
|:---|:---|:---|
| 判据 | 最多**一个**自建后端微服务 + 管理页 + 球端工具 | 体量大、一个服务装不下、**多服务**组成、子系统级 |
| 球端前端 | 通常有（Capability 面板） | **可以有**（ai-assistant-mcp 先例），非必需 |
| 管理面 | 无或简单配置页（admin-ui 远程页） | admin-ui 远程页 + 菜单注册（`data/menu.json` 声明式） |
| 后端 | 零/薄后端 | 多组件（自研 + 开源镜像混合），组件版本轴 |
| 目录 | `extensions/tool/<tier>/<pkg>` | `extensions/system/<tier>/<pkg>` |

> 退役注记：旧 `class` 四值（core/system/infra/tool）已于 2026-10-05 全退役（manifest 删字段、
> publish 不查）；旧 `domain` 域分组设计亦已撤回（ADR-005，rm_domain/域视图下线）。新包只填
> track/tier（+按需 delivery）。注意：菜单号段的 core/tool/system 百万段是**菜单 band 分类**，
> 与已退役的包 class 同名不同概念，号段申请见 L5-R5。

## 1.4 环境拓扑

| 环境 | 位置 | 用途 | 访问 |
|:---|:---|:---|:---|
| 测试底座 `ext-test` | 平台方在 DGX（192.168.1.22）microk8s 部署的独立 namespace | 插件团队开发自测专用，与生产完全隔离（独立 DB/MinIO bucket/SSO 全链） | 18850 / 18880（地址表见 `test-env/README.md`） |
| 生产 | 平台方私有 microk8s + docker-compose | 平台方统一发布 | 18850 / 18880 |

- 团队**本地零底座依赖**：构建/类型检查/单包自测全部在模板仓内完成；
  联调与「球上可见」依赖测试底座，由平台方 publish test 后提供。
- 时区：全部服务与容器统一 **Asia/Shanghai**（北京时间）；插件的 deployment 必须显式
  `env: TZ=Asia/Shanghai`（一票否决项）。

## 1.5 名词表

| 名词 | 含义 |
|:---|:---|
| 能力包 / 插件 | 独立开发、独立发布的能力单元（manifest + 前端/后端/数据） |
| Capability | 球端插件框架（CapabilityContext = 插件与平台交互唯一入口） |
| manifest.json | 包元数据唯一事实源（id/version/track/tier/delivery/components/backendServices…） |
| components 段 | 组件构成【前/后/菜/数据】**显式声明**（frontend/backend[]/adminUi/menu{enabled,menuPath}/data），禁止推导 |
| track / tier | 二维分类：track=体量维（tool/system），tier=归属维（platform/business）；显式必填零推断 |
| delivery | 交付维：bundled 标配 / optional 选装（仅 tool·business 象限用） |
| data/menu.json | 管理面菜单声明式事实源（批4 起替代菜单 SQL）；publish 时 menu-provision 幂等落地 |
| admin-ui | 管理面远程页面（ADR-007），随包发布、运行时远程加载 |
| 远程加载 | 球端插件唯一加载路径：产物传 MinIO，宿主按清单 registerRemote |
| 现场分组隔离 | ADR-006：每包独立 CustomDataSource，实体只走 ctx.entities |
| 测试底座 | DGX ext-test：平台方部署的独立测试环境（DGX microk8s namespace ext-test） |
| 提测单 | 团队自测通过后提交的平台方集成发布申请（代码+版本+CHANGELOG+自测证据+依赖清单） |
| 四必备 | manifest.json / VERSION / README.md / CHANGELOG.md |
| 版本五处一致 | VERSION / manifest.json / frontend/package.json / manifest.ts / container build.sh |
| @cesiumai/* | 模板仓 vendored 共享包（sdk-types/vite-config/ui-utils/admin-sdk） |
