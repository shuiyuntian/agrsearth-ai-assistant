# L8 提测与发布

> **测试底座自助发布**：团队用 `tools/publish.sh` 自发布到 agrslab-dev 测试底座（需平台方开通
> ext-developer 角色并下发凭据，见 `test-env/README.md`），可自助迭代调试（含 `--dev-url` HMR 回路）。
> **生产发布权仍在平台方**：团队交付终点 = 提测单；平台方验收依据 =
> 平台仓 `docs/运维手册/2-部署与变更/PLUGIN_ACCEPTANCE.md`。

## 8.1 全流程

```text
团队                              平台管理方
 │                                   │
 ├─ 1. 自测通过（RELEASE_CHECKLIST）  │
 ├─ 2. tools/publish.sh ──▶ agrslab-dev 测试底座自助发布（联调迭代）
 ├─ 3. 提交提测单 ──────────────────▶│ 4. 受理检查（要素完整性）
 │                                   │ 5. 代码 review（红线 grep + 契约核对）
 │                                   │ 6. publish test（agrslab-dev 底座复核）
 │                                   │ 7. 18850-t / 18880-t 实测（四菜单逐行对账）
 │                                   │ 8. publish prod（isDefault 人工点选=发布审核闸）
 │                                   │ 9. 观察窗（异常即回滚）
 │◀──────── 10. 归档提测单 ──────────┤
```

- 团队测试底座隔离：自助 publish **只进**测试底座（`tools/publish.sh` 拒绝一切 prod 参数），
  生产清单由平台方发布通道独占。
- 规模化后再议团队 scoped token；本期靠「提测制 + ownerTeam 登记 + 流程约定」。

## 8.2 提测单模板

```markdown
# 提测单：<包 id> v<版本>

- 团队/负责人：<团队名> / <姓名>（ownerTeam 登记名）
- 包 id / track / tier（/ delivery）：<pkg> / tool|system / platform|business（/ bundled|optional，仅 tool·business 象限）
- 版本：<x.y.z>（五处一致）
- 代码：PR 地址 / 压缩包（含完整包目录）
- CHANGELOG：本版变更段（贴最新段）
- components 声明：frontend/backend[]/adminUi/menu/menuPath/data = …
- 依赖清单：
  - 跨包 dependsOnPackages：…（无则写无）
  - 第三方服务/密钥注入需求：…（无则写无）
  - 网关路由新增需求：apiPrefix …
  - 菜单号段申请：…
- 自测报告：
  - npm run check 结果（贴输出摘要）
  - 测试底座实测截图：球端面板 / 管理页 / 关键接口
  - 已知问题与限制：…
```

## 8.3 发布前自检

团队侧按仓根 `RELEASE_CHECKLIST.md` 逐项勾选；平台方按 `PLUGIN_ACCEPTANCE.md` 逐项验收，
任一项不通过即退回补件。

## 8.4 测试底座自助发布（tools/publish.sh）

团队自测通过后、提交提测单之前，可自助发布到测试底座联调（账号与地址见 `test-env/README.md`）：

```bash
# 自助发布（构建 → MinIO 上传 → resource-manager 注册，仅测试底座）
MINIO_ACCESS_KEY=... MINIO_SECRET_KEY=... RM_TOKEN=... ./tools/publish.sh packages/<pkg>

# HMR 调试回路：把球端 entries.url 指到本机 dev server（vite build --watch + 静态服务）
./tools/publish.sh packages/<pkg> --dev-url http://<本机IP>:<port>
./tools/publish.sh packages/<pkg> --dev-url --reset   # 恢复正式产物 URL
```

约束（违反即拒）：

- 本脚本**只打测试环境**；prod/生产参数一律拒绝（生产发布由平台管理员执行）；
- 首次发布前需平台方开通 `ext-developer` 角色并下发 MinIO/网关凭据；
- 服务端菜单号段台账校验在主仓侧提测评审时由管理员执行（本脚本只跑本地 menu.json 校验）。

## 8.5 回滚

- 平台方执行：重新部署上一已发布版本（资源中心保留全部历史版本）；
- 团队配合：提供回滚验证点（上一个稳定版的关键行为清单）；
- 数据迁移类变更必须提供**反向 SQL/降级脚本**或在提测单声明不可回滚点。
