# L8 提测与发布

> **测试底座自助发布**：团队用 `tools/publish.mjs` 自发布到 aiearth01 共享开发调试环境（需平台方开通
> 团队角色并下发凭据，见 `test-env/README.md`）。macOS/Ubuntu 经 `tools/publish.sh`、Windows 经
> `tools/publish.cmd` 调用同一 Node 实现，可自助迭代调试（含 `--dev-url` HMR 回路）。
> **生产发布权仍在平台方**：团队交付终点 = 提测单；平台方验收依据 =
> 平台仓 `docs/运维手册/2-部署与变更/PLUGIN_ACCEPTANCE.md`。

## 8.1 全流程

```text
团队                              平台管理方
 │                                   │
 ├─ 1. 自测通过（RELEASE_CHECKLIST）  │
 ├─ 2. tools/publish.sh ──▶ aiearth01 共享调试环境自助发布（联调迭代）
 ├─ 3. 提交提测单 ──────────────────▶│ 4. 受理检查（要素完整性）
 │                                   │ 5. 代码 review（红线 grep + 契约核对）
 │                                   │ 6. publish dev（开发支撑环境复核）
 │                                   │ 7. 18850 / 18880 实测（四菜单逐行对账）
 │                                   │ 8. publish prod（isDefault 人工点选=发布审核闸）
 │                                   │ 9. 观察窗（异常即回滚）
 │◀──────── 10. 归档提测单 ──────────┤
```

- 团队测试底座隔离：自助 publish **只进**测试底座（`tools/publish.sh` 拒绝一切 prod 参数），
  生产清单由平台方发布通道独占。
- 规模化后再议团队 scoped token；本期靠「提测制 + ownerTeam 登记 + 流程约定」。

## 8.3 发布前自检

团队侧按仓根 `RELEASE_CHECKLIST.md` 逐项勾选；平台方按 `PLUGIN_ACCEPTANCE.md` 逐项验收，
任一项不通过即退回补件。

带公开后端的包先执行 `node tools/check-api-contract.mjs extensions/<track>/<tier>/<pkg>`：
前端/管理页 `src/api/index.ts` 与后端公开 Spring Mapping 全路径双向对账，业务文件散落本包
服务 URL 也会报错。`publish.mjs --check-only` 与正式发布均自动执行该闸口，失败时不触网、不发布。

## 8.4 测试底座自助发布（publish.mjs + 双 shim）

团队自测通过后、提交提测单之前，可自助发布到测试底座联调（账号与地址见 `test-env/README.md`）：

```bash
# macOS / Ubuntu：构建 → DC release-prepare → upload-sessions+MinIO 直传+complete → release-complete
AGRSEARTH_TOKEN=... ./tools/publish.sh extensions/<track>/<tier>/<pkg>

# Windows CMD / PowerShell（同一 Node 实现）
# tools\publish.cmd extensions/<track>/<tier>/<pkg>

# HMR：终端 A 跑 npm run dev（watch）；终端 B 跑 npx vite preview --outDir dist --host 0.0.0.0 --port <端口>
# manifest 必须指向实际 ESM 文件，不是 preview 根路径
./tools/publish.sh extensions/<track>/<tier>/<pkg> --dev-url http://<本机IP>:<port>/tool.es.js
./tools/publish.sh extensions/<track>/<tier>/<pkg> --dev-url --reset
```

约束（违反即拒）：

- **只打测试环境**；prod/生产参数一律拒绝（生产发布由平台管理员执行）；
- 发布控制 API **只走 developer-center**（`AGRSEARTH_TOKEN` 认证）——禁止直连
  resource-manager、禁止客户端自签 MinIO SigV4，亦不需要 MinIO 账号/密钥；
- 发布协议与产物处理由 Node 完成，不依赖 bash/jq/curl/python；npm 构建和可选
  `kubectl kustomize` 仍属项目构建工具链；
- 本机网络隔离时使用 `AGRSEARTH_SOCKS_PROXY=socks5h://127.0.0.1:51080`，DC、MinIO 和冒烟同走 SOCKS5；
- 首次发布前需平台方开通团队角色并下发团队 token；菜单号段经 DC 资源位申请与复核；
- 带数据库的后端无需手填 Secret 名：DC deploy 自动把 `DB_URL/DB_USERNAME/DB_PASSWORD/DB_SCHEMA`
  收敛到本包 runtime Secret；`data/sql/*.sql` 随 release-complete 按 SHA-256 幂等应用，回执含 applied/skipped。

## 8.5 启用/停用与回滚

- **启用/停用（2026-10-18 B+ 定版）**：管理面「工具扩展」页对包的三动作——启用=按默认版本拉起（首启=bundle 安装，已停用=拉回，纯前端=宿主加载）；停用=整包组件停止（scale 0，**数据/卷/注册用户全保留**）；升级=平台方设默认版本后启用生效。包有平台强依赖组件时可声明 `manifest.json` 的 `lifecycle.stoppable: false` 禁停（sso 类基础组件平台内置禁停）。
- **回滚**：平台方执行——对上一已发布版本重新「启用」（资源中心保留全部历史版本）；
- 团队配合：提供回滚验证点（上一个稳定版的关键行为清单）；
- 数据迁移类变更必须提供**反向 SQL/降级脚本**或在提测单声明不可回滚点。

## 8.6 后端两态联调（本地开发态 ↔ 底座验证态）

后端调试分两个形态，按阶段切换（前端另有 HMR 回路，见 §8.4）：

**开发态——本地起服务**（调代码、调接口、前后端联调的日常姿势）：

```bash
cd extensions/<track>/<tier>/<pkg>/backend/<svc>
mvn spring-boot:run
```

- 骨架 `bootstrap.yml` 的 Nacos discovery/config **默认直指 aiearth01 共享底座**
  （`10.82.11.51:18810`，可 `SPRING_CLOUD_NACOS_DISCOVERY_SERVER_ADDR` /
  `SPRING_CLOUD_NACOS_CONFIG_SERVER_ADDR` 环境变量覆盖）；配置 import 为 `optional:`——
  底座配置中心没有你的 dataId 也照常启动；
- 服务起来即注册进底座 Nacos → 网关按 `apiPrefix` 把 `/<svc>/**` 路由到你本机实例，
  前端 HMR 回路可直接调通真后端；
- **双向可达**是前提：本机 → 底座 Nacos（注册/拉配置），底座网关/Pod → 本机（回调）。
  公司网/Tailscale 天然满足；仅单边可达表现为「能注册但请求超时」；不在内网时的
  平台惯例是经 SSH 隧道连底座（见 `bootstrap.yml` 头注释）。

**验证态——`publish --deploy` 推底座**（以下只能集群验证，本地替代不了）：

- **镜像形态**：Dockerfile / 基础镜像 / 启动命令 / JAVA_OPTS——本机跑 jar 能过不代表打进镜像能过；
- **k8s 行为**：健康探针路径、`resources.limits`（OOMKilled 137 只有集群里才暴露）、ConfigMap 注入、TZ 时区；
- **集群内寻址**：其他 Pod 按 ClusterIP DNS 调你的服务（本机实例注册的是笔记本 IP，集群内未必回得去）；
- **给他人使用**：团队伙伴/平台方访问时，你不能一直开着笔记本。

**共享环境注意事项**：开发态实例注册进的是**共享** Nacos——底座网关可能把别人的联调流量
也路由到你的笔记本；你停服务即 503（直至实例注销）。结束调试及时停服；长时稳定的验证
回到验证态（推底座部署）。
